# Privora Panel 5.0.0-dev.6.29 — DNS Zone Editor, Glue Automation & Website Lifecycle Repair

Prepared 2026-08-20 from the 5.0.0-dev.6.27 candidate.

## Fixed

- Privora-generated Nginx vhosts are recognized as Privora-managed even when the Linux hosting account was adopted from another provider, so Delete Website works for Privora-created sites.
- A `www` alias in the same Nginx server block is collapsed into the apex website instead of appearing as a duplicate website.
- DNS Zones now reads the actual Privora-managed BIND zone file and displays live records.
- Administrators can add/update/delete A, AAAA, CNAME, MX, TXT, CAA and non-root NS records and delete whole non-nameserver zones.
- Website creation seeds the standard web/mail DNS baseline: root A/AAAA, www, ftp, mail, MX, webmail, autodiscover, SPF, DMARC and CAA; SOA/NS are generated by the authoritative-zone renderer.
- Nameserver configuration always creates local A/AAAA glue for ns1/ns2 and updates the authoritative NS pair even when the base zone already exists.
- The obsolete `registrar-glue-required` placeholder status is removed. Local glue and registrar/registry glue are reported separately.
- A Privora-compatible registrar adapter can automatically synchronize registry child-host/glue records and delegation on nameserver update, and delete them on nameserver removal.
- Nameserver Manager now supports deletion. Dependent managed zones require an explicit force/reassignment operation and are safely rewritten to per-zone ns1/ns2 authority before the global pair is cleared.

## Registrar adapter contract

The privileged agent reads optional protected environment variables from `/etc/privora-panel/agent.env`:

- `PRIVORA_REGISTRAR_PROVIDER`
- `PRIVORA_REGISTRAR_ADAPTER_URL`
- `PRIVORA_REGISTRAR_TOKEN`

The adapter must expose authenticated JSON POST endpoints `/v1/glue/sync` and `/v1/glue/delete`. Privora never claims registry glue is synchronized when no registrar adapter is connected.
