# Privora 5.0.0-dev.6.62 — Hosted DNS Creation & Update Reliability Repair

## Live regression that identified the root cause

Older hosted domains (`privoralabs.org`, `velvet-vixxen.com`, `privategather.com`) remained configured, while later-created `demo.privategather.com`, `downloads.privoralabs.org`, and `privoralabs.com` appeared not configured. This exposed a creation-path regression rather than a display-only DNS inventory problem.

## DNS creation repair

- Generic Create Website now detects an existing hosted parent zone.
- A child hostname such as `demo.privategather.com` is provisioned as a record in `privategather.com`, not as an independent child DNS zone.
- Create Website and Add Subdomain now share parent-zone DNS classification behavior.
- Root-domain provisioning creates/verifies the root authoritative zone.
- Added `POST /v1/dns/repair-hosted` for in-place repair of previously half-created hosted DNS state.
- Added automatic post-update hosted-DNS reconciliation after the deferred agent refresh.
- DNS inventory remains fail-soft: known hosted domains stay visible even if BIND inspection fails.

## Update reliability

- Migration preflight/apply remain timeout-bounded.
- Active PCC PHP-FPM is gracefully reloaded after promotion instead of being hard-restarted, preserving file-backed PCC sessions while avoiding stale PHP/opcache workers.
- Update/status transaction polling falls back to local VERSION/journal state if the agent is temporarily unavailable during its deferred refresh.

## PPanel access

- PPanel login identity is the hosting account primary domain rather than the raw Linux username.
- PCC Hosting Accounts exposes Set/Reset PPanel Access.
- Imported accounts can have PPanel access configured without renaming the Linux account.
