# Privora 5.0.0-dev.6.65 — Per-Domain Nameserver Selection, Package Inventory Resilience & PPanel Usernames

Live comparison showed an older/default branded-nameserver domain (`privategather.com`) configured correctly while a later domain (`privoralabs.com`) with its own nameserver set remained NOT CONFIGURED.

Root causes addressed:
- root-zone provisioning and hosted-DNS repair selected the global/default nameserver set instead of an exact nameserver set belonging to the target domain;
- package inventory allowed apt/dnf to consume the same deadline as the PCC client, risking an empty/partial agent response and `Invalid response from agent`;
- PPanel access only used the primary domain as the login identity and did not let PCC assign a customer-facing panel username.

6.65 behavior:
- exact domain-specific nameserver set wins for root-zone create/repair; default is fallback only;
- package inventory uses a shorter agent-side deadline and returns valid degraded JSON when the package manager is slow/locked;
- PCC can create or rename a PPanel username independent from the Linux hosting account;
- PPanel usernames are collision-checked case-insensitively;
- the primary domain remains an alternate PPanel login alias;
- renaming a custom PPanel username removes the stale prior username.

Certification:
- complete verification train passed through the historical 6.60 gate before execution-window cutoff;
- remaining 6.60→6.65 gates were rerun separately and passed;
- exact 6.65 Update Center ZIP verified with the 6.64 upload verifier and embedded stable release trust key.
