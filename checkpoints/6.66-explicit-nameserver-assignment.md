# Privora 5.0.0-dev.6.66 — Explicit Nameserver Assignment & Core Status Fail-Soft

Live pattern: `privoralabs.org` was observed publishing `ns1/ns2.privoralabs.org` even though the intended nameserver pair was `ns1/ns2.privoralabs.com`. The 6.65 exact-domain nameserver preference could select a same-name set merely because its base domain matched the hosted zone.

6.66 changes:
- adds explicit hosted-domain → nameserver-set assignments;
- unassigned domains use the administrator-selected default set rather than inferring from the domain name;
- PCC Nameserver Manager exposes domain assignment controls;
- assignment changes immediately reconcile the managed BIND zone;
- existing apex NS records are rewritten to the assigned/default pair;
- stale in-bailiwick A/AAAA glue for retired nameserver hostnames is removed when switching to a different nameserver set;
- Update Center core-status request failures degrade to the locally known installed version when package status remains available instead of showing CORE STATUS UNAVAILABLE.

Certification:
- full verification passed through all core/update/signing/recovery gates before the execution window expired in the historical tail;
- all remaining 6.56–6.66 gates passed separately;
- exact signed 6.66 update ZIP passed the 6.65 verifier and archive integrity checks.
